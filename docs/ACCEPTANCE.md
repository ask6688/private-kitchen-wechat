# 验证范围与人工检查

## 自动检查

在项目根目录运行 `npm test`。测试使用真实业务代码、内存云 SDK 和模拟微信 API，不连接真实厨房，也不写入用户数据。

覆盖范围：

- 空间成员、越权访问、邀请、移交和退出
- 菜品与心愿的关联、分类标签、归档、版本冲突及草稿恢复
- 选菜合并、饭单确认/完成/取消、重复请求和丢失响应
- 已有菜、新菜及独立制作记录、制作次数、单菜与整餐照片来源
- 最近记录单条/批量删除、失败重试和相关列表同步
- 导航来源、冷启动无上页返回、迟到请求及保存后跳转
- 图片压缩、二进制上传、失败保留和引用保护
- Menu 长标题/菜名、不同菜数、图片与分类间距、实际字形轮廓和导出竞态

GitHub Actions 运行同一命令，结果可从仓库的 Checks 查看。

## 实际运行与待验证项

项目曾在微信开发者工具和实际 CloudBase 环境走通单账号的菜品保存、照片上传读取、饭单和记录流程。README 展示图另使用虚构数据和原创插画，由当前模板本地渲染，不展示真实厨房资料。

以下仍需在自己的环境验证，自动测试或展示图不能替代：

- 最新完整 Menu 在真机上的字形、图片、导出与长内容表现
- 两台手机同时编辑、真实网络中断和恢复
- 新环境的数据库索引、存储安全规则及请求域名配置
- 第三个非成员账号的实际越权拦截
- JSON 及云照片在独立环境的备份恢复；JSON 不包含原图
- 正式发布所需的隐私、类目、备案及内容安全要求

## 建议的人工闭环

1. A 创建厨房，邀请 B 加入，两人看到同一空间
2. 各自添加菜品或心愿，补一张相册照片
3. 从菜单与心愿选菜，合入同一份饭单并确认
4. 完成这顿饭，保存单菜或整餐照片与心得
5. 从最近记录进入同一 Menu 详情，查看并导出完整图
6. 改名、归档来源菜品后检查历史快照，再编辑和删除专用测试记录
7. 验证失败输入保留、退出成员失去访问权和导出恢复

测试删除只使用新建的专用记录，实际厨房数据由使用者自行管理。
